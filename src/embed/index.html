Embedding the playground

A documentation page can put a running abap2UI5 app next to the code that produces it. This page is that documentation, and every demo on it is real — the same playground, in an iframe.

A demo with the editor

The reader can change the ABAP and press Run. data-src points at the same file the documentation prints, so the printed code and the running code cannot drift apart. 

<div class="abap2ui5-demo"
     data-src="https://raw.githubusercontent.com/.../z2ui5_cl_demo.clas.abap"></div>
<script src="https://abap2ui5.github.io/test-live/embed/abap2ui5-embed.js"></script>

A demo without the editor

data-view="app" shows the result on its own, for a paragraph that is about what the app does rather than how it is written. It still compiles and runs the ABAP, and it reports its height so the frame fits what was rendered instead of guessing.

Code that lives only in this page

data-code carries the ABAP itself, deflated into the playground's URL fragment. Nothing has to be hosted.

Why nothing loads until it is clicked

Each demo is a complete ABAP runtime plus an abaplint parse of nine hundred sources — a second or two of processor and a few hundred megabytes, per frame. Demos on the same page share the browser's cache, so the bytes are paid once, but the parsing is not. A page with ten examples that all booted on scroll would be the slowest thing in the manual, so each one stays a button until somebody wants it. data-auto="1" overrides that for a page that is only about its one demo.
